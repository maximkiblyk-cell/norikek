# NØRI v0.8.3 — аудит GitHub и подготовка Windows CI

## Фактическое состояние

Репозиторий `https://github.com/maximkiblyk-cell/norikek` публичный; GitHub API вернул размер 0 и default branch `main`, список веток пуст, `git ls-remote` не вернул refs. Существующих файлов и коммитов для сравнения не обнаружено. В локальном пакете — исходный проект v0.8.3; в начале он не был Git worktree. Содержимое подготовлено в отдельной локальной ветке `stabilization/v0.8.3`, без удаления данных и изменений backend. Первый push следует делать только после повторной проверки, что удалённый репозиторий всё ещё пуст.

Подключённая GitHub MCP-сессия подтвердила аккаунт `maximkiblyk-cell`, но создание файла вернуло `403 Resource not accessible by personal access token`; ветку создать не удалось (в пустом репозитории нет исходного ref `main`). CLI авторизация впоследствии подтверждена для того же аккаунта, права push проверены. На момент исходного аудита репозиторий оставался пуст; текущий статус загрузки и CI необходимо сверять с GitHub и фактическим run.

## Предлагаемые исключения перед публикацией

В `.gitignore`: `.env` и `.env.*` (кроме трёх example), сертификаты и ключи (`*.pem`, `*.key`, `*.pfx`, `*.p12`, `*.p8`, `*.crt`, `*.cer`, `*.der`), `*.dpapi`, credentials/secrets JSON, SQLite/DB и журналы, Python caches/venv, редакторские файлы, CMake build директории и бинарники, логи и временные файлы. В подготовленной копии реальных конфигураций, ключей, локальных БД, сборок и логов с такими именами не обнаружено; исключать здесь фактически было нечего. Исторические архивы в `original/`, код сторонних зависимостей и PNG сохранены и планируются к передаче. В открытом репозитории документы, архивы и история будут публичными: перед публикацией владелец должен убедиться, что это приемлемо.

Локальная проверка staged файлов и содержимого вложенных архивов по шаблонам частых токенов Telegram/GitHub/AWS и PEM private keys не обнаружила совпадений. Это **не полная гарантия отсутствия секретов или личных данных**; необходимо проверить весь предполагаемый diff. Примеры `.env.example`, `.env.docker.example`, `.env.telegram-test.example` содержат пустые или фиктивные значения; не подставлять в них реальные секреты.

## Windows workflow

Изменён только `.github/workflows/windows-core.yml`: Windows Server 2022, checkout, подготовка MSVC, проверка доступного CMake с установкой через Chocolatey при отсутствии, установка curl/OpenSSL через vcpkg, configure, Debug/Release, CTest и проверка изоляции DPAPI другим профилем. Существующие тесты не отключены: `vault_write` проверяет шифртекст без test-secret, `vault_read` — чтение отдельным процессом, `vault_corrupt` — отказ при повреждении, отдельный скрипт проверяет изоляцию профиля. Синтаксис YAML и наличие шагов проверены локально. Это не подтверждает, что workflow работает на Windows, что установка зависимостей успешна или что DPAPI-тесты прошли. Переменный baseline vcpkg, права временной учётной записи и возможные зависимости DLL требуют настоящего CI.

## Ручной запуск, если доступ на запись не восстановлен

В чистой распакованной копии архива из корня проверьте, что remote всё ещё пуст: `git ls-remote --heads https://github.com/maximkiblyk-cell/norikek.git`. Если он больше не пуст — остановитесь и сначала сравните историю; не используйте force push. Пользователь авторизуется GitHub CLI через официальный device flow в своём браузере. Никогда не вставляйте токен в URL, команды, коммиты или чат. Публикация необратимо делает данные публичными.

```sh
git init -b stabilization/v0.8.3
git status --short
git add .
git status --short
git diff --cached --stat
git diff --cached              # внимательно проверить содержимое; не публиковать вывод с секретами
git commit -m "Prepare NØRI v0.8.3 stabilization"
git remote add origin https://github.com/maximkiblyk-cell/norikek.git
git push -u origin stabilization/v0.8.3
```

Установите Git user.name/user.email по своему желанию, учитывая публичность истории. Первая ветка пустого репозитория может стать default branch: проверьте настройки GitHub; существующий `main` не перезаписывать. На push должен быть создан workflow run, поскольку в ветке присутствует `.github/workflows/windows-core.yml`; в Actions откройте `Windows Core (development tests)` и дождитесь фактического окончания. Для ручного workflow_dispatch GitHub требует, чтобы workflow присутствовал на default branch; при необходимости согласуйте default branch с владельцем. Сохраните URL run, commit SHA, логи и реальные результаты всех шагов без секретов. На ошибке сборки или DPAPI сначала исправить причину и повторить тесты, не отключать проверки.

Существующие Linux-результаты — `V083_REPORT.md` — не подтверждают Windows. Игровые адаптеры и команды не включались. Нет реальной Telegram-валидации и Docker-валидации на полноценном host; это отдельные открытые задачи.
