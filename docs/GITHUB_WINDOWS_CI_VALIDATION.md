## DPAPI: реальные результаты и границы

- CTest `vault_write`: сохранение тестового значения через DPAPI; тест проверил, что файл не содержит plaintext тестового значения.
- `vault_read`: чтение отдельным процессом того же Windows-профиля.
- `vault_corrupt`: повреждённое хранилище отклонено.
- Отдельный тест создал временный второй Windows-профиль на runner: его собственный DPAPI работал, но он не смог расшифровать доступный ему ciphertext первого профиля. Тест завершился PASS.
- Эти проверки подтверждают только выполненные сценарии с тестовыми значениями на данном Windows runner; не полный аудит хранилища, не отсутствие любых возможных утечек, не повторный запуск реального development host и не отзыв/истечение через настоящий Telegram.

Ключевые строки без секретов — `evidence/github-ci/`; полные логи и SHA — по ссылкам запусков. Новый отчёт — документационный commit после протестированного commit; приложение и workflow в нём не менялись.

## Безопасность публикации

До загрузки список исключений был показан: реальные `.env`, credentials, ключи и сертификаты, базы, локальные сборки, кэши и логи. `.gitignore` расширен, примеры `.env.*.example` сохранены с пустыми/фиктивными значениями. Реальных секретных файлов соответствующих типов в подготовленной копии не было; исторические ZIP и PNG не удалены. Проверено 290 исходных/вложенных файлов по шаблонам частых GitHub/Telegram/AWS-токенов и PEM private keys, совпадений нет. Это не полная проверка безопасности или личных данных. Убедитесь, что публичное размещение содержимого и документов допустимо.

Предыдущие Linux результаты: `V083_REPORT.md`; после исправлений дополнительно Linux Release CTest 2/2 и локальный TLS-тест прошли. Windows CI не доказывает прохождение остальных требований MASTER PROMPT.
