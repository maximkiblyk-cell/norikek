# Отчёт о проверке v0.6.0

Дата: 23 ноября 2026. Linux, Python 3.13, временные SQLite и PostgreSQL 15; только тестовые данные.

## Выполнено

- Полный набор с `NORI_TEST_POSTGRES_URL`: **71 passed, 3 warnings**. Предупреждение Starlette/httpx и два Python warnings о fork в многопоточной среде. Тесты с PostgreSQL используют и удаляют отдельные случайные схемы.
- `tests/test_auth_v06.py` и `test_security_postgres_v06.py`: настоящая dependency авторизации без подмены — старый сервисный токен отклонён; сессии разных пользователей изолированы, actor ID нельзя подставить; роль user/admin/owner, назначение и отзыв роли, блокировка и отзыв сессий; тарифный срок, ограничения платформы и устройств; конкурентный лимит устройств PostgreSQL.
- `tests/test_bot_http_v06.py`: отдельный работающий uvicorn и реальная локальная HTTP-связь с ботом, реальная выдача и отзыв сессий, владелец, админ-меню и блокировка пользователя. Telegram transport и входящие обновления в этом тесте **фиктивные**; это не проверка Telegram polling или доставки.
- Регрессионные `test_api.py` и `test_postgres.py` проверяют прежнюю бизнес-логику через изолированный test-only shim авторизации; они не подтверждают новую авторизацию. Проверки новой авторизации перечислены выше, без shim.
- Интеграционные тесты создали схемы v0.4 и v0.5 из сохранённых исторических архивов; проверили перенос в копию SQLite, включая пользователя, лицензию и обращение, сохранность исходного файла, запрет перезаписи и отказ на неизвестной схеме. Отдельно прошёл вариант v0.5 Alembic.
- На отдельной PostgreSQL 15 последовательно выполнены миграции исходной версии v0.5, добавлена запись пользователя, выполнены upgrade до v0.6 и `alembic check`; запись сохранилась.

## Не проверено

Настоящий Telegram polling/доставка (тестовый токен не предоставлен), реальный Windows, сборка и запуск Docker/Compose (Docker отсутствует), автоматический перенос неверсированной PostgreSQL, реальные игры и платежи, нагрузка и независимый security-аудит. Тестирование не делает проект production-ready.
