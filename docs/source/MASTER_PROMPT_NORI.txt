# 1. ИНФОРМАЦИЯ О ПРОЕКТЕ

Название: NØRI Reseller Helper

Платформы:
- Hassle RP 2.0
- Radmir CRMP

Категория:
Gaming Plugin / Reseller Assistant / Telegram Integration.

Основная идея:

Создать собственный игровой плагин с внутриигровым интерфейсом и интеграцией Telegram.

Игрок устанавливает компоненты NØRI, запускает игру, открывает собственное меню непосредственно внутри игры, настраивает функции и подключает Telegram.

Telegram используется для получения игровых уведомлений, отправки ответов и удалённого управления доступными функциями.

NØRI должен стать самостоятельным коммерческим продуктом с собственной идентичностью, лицензиями, подписками, установщиком, обновлениями и административной системой.

Главный ориентир по функциональности — Reseller Helper v0.1.5.

Главный ориентир по визуальной идентичности — предоставленная фотография с готической серебряной типографикой HASSLE/RADMIR PLUGIN.

Не копировать чужой проприетарный код, бренд, логотипы или внутреннюю реализацию. Создать собственную реализацию и собственный дизайн.

# 4. ГЛАВНАЯ ЦЕЛЬ — СОЗДАНИЕ ИГРОВОГО ПЛАГИНА

Самая важная часть проекта.

Мы не хотим, чтобы обычный покупатель использовал техническое Tkinter-приложение с полями:

- API URL.
- Pairing Code.
- API Device Secret.

Это внутренняя техническая конфигурация.

Клиентский продукт должен быть совершенно другим.

Наша конечная цель — собственный игровой плагин NØRI с внутриигровым интерфейсом.

Предполагаемый пользовательский сценарий:

1. Покупатель приобретает лицензию через Telegram.
2. Получает доступ к установщику NØRI.
3. Выбирает Hassle RP или Radmir CRMP.
4. Устанавливает необходимые компоненты.
5. Запускает игру.
6. Открывает меню NØRI непосредственно внутри игры.
7. Настраивает игровые функции.
8. Привязывает Telegram.
9. Получает уведомления и использует доступные функции.

Ориентир по установке оригинального Reseller Helper:

- Два DLL-файла.
- Размещение в предполагаемой игровой директории.
- Запуск игры.
- Открытие меню клавишей Insert или командой /rh.

Однако не считать эту схему автоматически совместимой с нашими DLL.

Сначала определить разрешённый механизм загрузки собственного плагина.

Не применять несанкционированную DLL injection, обход античита, скрытое чтение памяти игры, перехват паролей или неразрешённое вмешательство в процесс игры.

Если необходим SDK или разрешение разработчика, указать это прямо.

Не создавать фиктивную DLL, которая только показывает меню, но не получает настоящие игровые события.

# 6. TELEGRAM BOT — ПОЛНОЦЕННЫЙ ПРОДУКТ

Telegram Bot должен быть не просто средством отправки сообщений.

Он должен стать полноценной системой управления подпиской и игровыми уведомлениями.

Основные разделы:

- Главное меню.
- Подключение игры.
- Лицензия.
- Мои устройства.
- Уведомления.
- История.
- Поддержка.
- Административная панель.

## Уведомления

### SMS

При поступлении SMS отправлять пользователю сообщение:

- Заголовок «Новое SMS».
- Ник отправителя.
- Игровой номер.
- Текст сообщения.
- Время получения.
- Кнопка «Ответить».

### Ответ на SMS

Пользователь нажимает «Ответить».

Бот запрашивает текст.

После ввода:

- Создаётся уникальная команда.
- Проверяется привязка устройства.
- Команда помещается в очередь.
- Пользователь получает подтверждение постановки в очередь.
- Игровой адаптер получает команду через разрешённый интерфейс.
- После подтверждения пользователь получает статус отправки.

Нужны статусы:

- pending.
- processing.
- sent.
- failed.
- expired.

Не показывать статус sent, если игра фактически не подтвердила отправку.

### Входящие звонки

Уведомления:

- Ник.
- Номер.
- Время.
- Игровая платформа.

### Очередь

Пользователь получает информацию:

«Ваше место в очереди: 20».

Предусмотреть уведомления при достижении заданного порога.

### Объявления

Передавать подтверждённые игровые объявления с информацией об авторе и содержимом.

# 8. БЕЗОПАСНОСТЬ

Безопасность — обязательное требование.

Не собирать:

- Пароли.
- Cookies.
- Telegram session strings.
- Историю браузера.
- Clipboard.
- Keystrokes.
- Посторонние данные окон.
- Скриншоты без явного действия пользователя.
- Личные файлы.

Не использовать скрытую телеметрию.

Не загружать старые DLL из оригинального архива.

Не запускать неизвестные бинарные файлы.

Все запросы к Backend должны проверять авторизацию.

Обеспечить изоляцию пользователей и устройств.

Не допускать подмены User ID.

Учитывать повторную доставку, истечение времени и replay attacks.

DPAPI использовать для локального хранения секретов Windows.

Device revoke должен выполняться на Backend, а не только через очистку локальных файлов.

Если устройство офлайн, показывать, что серверный отзыв ещё не подтверждён.
