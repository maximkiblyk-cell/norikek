# v0.8.1 — ограниченный security review

Это внутреннее инженерное ревью с автоматизированными тестами, не независимый аудит и не утверждение production-безопасности.

| Область | Проверено / остаточный риск |
|---|---|
| RBAC и чужие ресурсы | Существующие реальные сессии user/admin/owner, подмена actor, чужие grant/device/commands и disabled покрыты интеграционными тестами; часть старых тестов использует auth shim. Безопасность доверенного Telegram ingress зависит от токена, БД и процесса бота. |
| Credentials | Устройство идентифицируется bearer verifier в БД, grant и account проверяются сервером. Отзыв устройства отклоняет следующие запросы; client очищает vault при 401. 401 может означать и неверный credential, а не только отзыв. Прерывание уже начавшейся операции не гарантируется. |
| Pairing | Код и claim одноразовые, TTL ограничен, лимиты в БД и запрет replay протестированы. В v0.8.0 C++ стирал claim secret даже при достоверном 409 «ещё не подтверждено»: исправлено сохранение только при этом определённом ответе. При неопределённой ошибке выдачи секрет уничтожается, владелец должен отменить привязку и начать заново. |
| Сроки/сеть | Индикатор `LicenseGate::online()` больше не остаётся online после проверенного срока; после сбоя refresh очищает разрешение; игровые команды по-прежнему запрещены. Транспорт требует HTTPS, проверяет сертификат и имя. Host должен вызывать refresh при reconnect и не работать с сетевыми функциями в UI-потоке; GUI пока не подключён. |
| Windows vault | Код DPAPI CurrentUser переписан на ограниченное чтение и запись ciphertext через новый временный файл с flush и заменой. Защита при сбое, ACL, DPAPI, изоляция другого Windows-профиля и собственно сборка **не проверены на Windows**. Копии строк и сетевых библиотек в памяти не гарантированно затёрты: не обещать полное уничтожение секрета в памяти. |
| Rate limits | Проверены DB-backed лимиты pairing и устройства; это фиксированные окна по адресу прямого peer, не безопасная настройка обратного прокси, не защита от распределённой нагрузки и не все legacy endpoints. Нужны edge protection, proxy policy и очистка buckets. |
| Validation и логи | Тесты проверяют sanitization v2 и отсутствие известного секрета в 422; SQL параметры скрыты. Нет доказательства redaction всех proxy/access/отладочных логов и дампов, production конфигурацию требуется отдельно проверить. |
| События и данные | Типы отключены по умолчанию. Если включить, payload сохраняется в БД открытым текстом без срока удаления, возможно содержит PII. Политика retention, encryption, удаление, контроль доступа и операция cleanup не утверждены/не реализованы. Не включать типы до их решения. |
| Конкуренция/отзыв | Тесты проверки лимитов и ряда очередей есть; полная сериализация блокировки аккаунта с уже выполняющимися операциями, стресс/гонки и сбои инфраструктуры не доказаны. Требуется отдельный threat model и аудит. |

Внешние запросы/endpoint /v2 по HTTP из production не допустимы: необходим проверенный TLS proxy. Не включать production оплаты, события или команды. Ни игровых SDK, ни подтверждения исполнения нет.
