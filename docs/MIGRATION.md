# Миграции в v0.6.0

Остановите API, бота и worker. Создайте резервную копию базы и проверьте восстановление. Никогда не применяйте изменения сразу к единственной production-копии. До переключения проверьте данные и все нужные сценарии; откат — возврат проверенной резервной копии и предыдущего кода. Миграция downgrade новых таблиц отключена, чтобы случайно не потерять данные.

## SQLite v0.4 / v0.5

Скрипт `scripts/migrate_sqlite_copy.py` принимает исходный путь и путь **нового** файла. Он читает исходник только для создания копии посредством SQLite backup API (включая committed WAL), сверяет columns, defaults, primary/foreign keys, индексы и SQL структуры с зафиксированными известными схемами из поставленных исходников; дополнительные таблицы, views, triggers и изменённые схемы отклоняет. Включены схемы SQLite v0.4 `create_all`, v0.5 `create_all` и v0.5 Alembic на ревизии `d296277344ed`.

Для v0.4 на копии создаются отсутствовавшие таблицы устройств, только затем ставится соответствующая проверенная базовая ревизия и запускаются остальные миграции. Для v0.5 по проверенной схеме выполняется правильный upgrade. Целостность, внешние ключи и число строк старых таблиц проверяются до и после. Если команда не прошла, созданный файл назначения удаляется, исходная база остаётся нетронутой. Не полагайтесь исключительно на счётчики: проверьте содержимое и прикладные операции на копии перед переключением. Если формат не совпал — остановитесь и исследуйте схему вручную, не подделывая stamp.

Миграции не делают из старых лицензий оплаченные подписки и не назначают им тариф. Старые grants сохраняют совместимость: платформа `both`, лимит `DEVICE_LIMIT` на лицензию. Старую отдельную таблицу `licenses` и старые данные pairing сохраняют; они автоматически не становятся новыми grants.

## PostgreSQL

Проверена миграция версии v0.5, уже имеющей Alembic revision `d296277344ed`, до `f60e00000001`, на отдельной PostgreSQL 15 с тестовой записью и `alembic check`. Это не подтверждение всех реальных инсталляций. Стоп сервисы, физический или логический backup, восстановление в отдельную тестовую базу, настройка `DATABASE_URL` на копию, `python -m alembic upgrade head`, проверка данных и только затем план переключения. Скрипт SQLite для PostgreSQL не подходит. Безопасная автоматическая миграция **неверсированных** v0.4/v0.5 PostgreSQL пока отсутствует.

## Обратная совместимость

API v0.6 отклоняет общий сервисный токен. Задайте `OWNER_TELEGRAM_IDS`, создайте админов владельцем; старый `ADMIN_TELEGRAM_IDS` игнорируется. Все бот/worker/API должны использовать одну БД; API не выдаёт сессии по произвольному Telegram ID. Настройка окружения, процессы и внешний TLS требуют отдельной проверки.
