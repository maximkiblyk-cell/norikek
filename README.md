# 🖤 NØRI v0.6.0 — исходный код тестового контура

**Проект не является готовым коммерческим продуктом; MASTER PROMPT не выполнен.** В архиве сохранены полученный starter и сборки v0.4/v0.5, а также обновлённый код. Более полный прежний репозиторий и Sidecar не предоставлены. Работайте с тестовыми данными и отдельным тестовым ботом.

## Изменения v0.6.0

- API больше **не принимает общий `SERVICE_TOKEN`**. Для каждого частного Telegram-обновления доверенный процесс бота создаёт краткоживущую случайную сессию, отправляет её API и отзывает после обработки. API проверяет пользователя сессии, доступ к его данным, совпадение actor ID и текущую роль в БД. Владелец задаётся через `OWNER_TELEGRAM_IDS`; только владелец управляет ролями администраторов. Отключение пользователя отзывает его активные сессии и запрещает device API.
- Расширена админка Telegram: пользователи, роли, блокировка, лицензии, устройства, тарифы и обращения; действия с подтверждением. Просмотр ограничен последними записями, не все административные сценарии завершены.
- Выдача лицензии по тарифу фиксирует срок, платформу и лимит устройств в лицензии. Изменение доступности тарифа не изменяет уже выданные права. Ручная выдача `/issue` сохраняется как устаревший ручной сценарий и использует обе платформы и глобальный лимит. Платежей нет; выдача администратором не означает оплату.
- Добавлена проверяемая миграция **в копию** для известных SQLite-схем v0.4/v0.5. Для версионированной PostgreSQL v0.5 проверен обычный Alembic upgrade на тестовой базе. Неизвестные схемы и неверсированная PostgreSQL требуют отдельного анализа.

Процесс бота — доверенный компонент с доступом на запись в ту же БД, что и API. Telegram Bot API подтверждает источник обновлений при штатном polling, но компрометация бота, токена Telegram, базы, хоста или конфигурации владельцев позволяет подменять пользователей. Краткоживущий bearer при перехвате действует от своего пользователя до отзыва/истечения. Нет законченного внешнего TLS-контура, rate limits, security-аудита, изолированных DB-ролей и полноценной защиты от злоупотреблений. **Не используйте систему в production и не публикуйте API наружу.**

## Первый запуск новой пустой SQLite

Нужен Python 3.11–3.13. Windows PowerShell из папки проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
# Заполните BOT_TOKEN и OWNER_TELEGRAM_IDS в .env
.\.venv\Scripts\python.exe -m alembic upgrade head
```

В `.env` задайте токен **отдельного тестового бота** BotFather и свой числовой Telegram ID в `OWNER_TELEGRAM_IDS`, например `123456789`. Для нескольких владельцев — ID через запятую. Секреты не отправляйте в чат и не добавляйте в ZIP. `SERVICE_TOKEN` и `ADMIN_TELEGRAM_IDS` больше не дают доступ: прежних администраторов владелец назначает заново через админку. Если владелец не настроен, административный доступ закрыт. Оставьте `DEVICE_PAIRING_ENABLED=false`.

В трёх отдельных окнах PowerShell из этой же папки:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# второе окно
.\.venv\Scripts\python.exe -m app.bot.main
# третье окно
.\.venv\Scripts\python.exe -m app.worker
```

На Linux/macOS используйте `python3 -m venv .venv`, `.venv/bin/python`, `cp .env.example .env` и `.venv/bin/python -m alembic upgrade head`; команды запуска модулей те же. Все процессы должны видеть **одну и ту же базу**, а бот должен иметь право записи в неё. Откройте бота и отправьте `/start`, затем владелец — `/admin`. Другие пользователи должны начать диалог с ботом до выдачи им лицензии или роли.

В `/admin`: выберите пользователя, посмотрите лицензии/устройства, подтвердите отключение или смену роли. Лицензии: `/issue TELEGRAM_ID ДНЕЙ`, `/extend ID_ЛИЦЕНЗИИ ДНЕЙ`, `/revoke ID_ЛИЦЕНЗИИ`; тарифы: `/plancreate НАЗВАНИЕ ЦЕНА_В_МИН_ЕД ВАЛЮТА ДНЕЙ УСТРОЙСТВ both|hassle|radmir`, затем `/grantplan TELEGRAM_ID ID_ТАРИФА`. Действия требуют подтверждения. Ключ показывается один раз; при потере ответа проверьте состояние и отзовите лицензию перед повторной выдачей. Не передавайте ключ в публичный чат. Обращения — в меню поддержки; включите системные уведомления хотя бы на одной платформе и запустите worker для очереди ответов. `sent` означает принятие Telegram API, не прочтение; возможны дубли.

Реальный Telegram и Windows не проверены в этой среде. `http://127.0.0.1:8000/health` и `/ready` — локальные проверки; защищённые маршруты требуют пользовательской сессии, которую создаёт доверенный Telegram ingress. Старые сторонние клиенты с `SERVICE_TOKEN` несовместимы намеренно. Не используйте его для обхода новой авторизации.

## Миграция старой базы

**Не запускайте первую миграцию поверх старой неверсированной базы и не используйте `stamp` вручную.** Остановите все процессы и выполните резервное копирование. Из каталога проекта:

```powershell
.\.venv\Scripts\python.exe scripts\migrate_sqlite_copy.py C:\path\old.db C:\path\nori-v06-copy.db
```

Linux/macOS: `.venv/bin/python scripts/migrate_sqlite_copy.py /path/old.db /path/nori-v06-copy.db`. Получатель должен быть новым файлом. Скрипт сравнит структуру с известными схемами, скопирует исходную БД через SQLite backup, выполнит миграции на копии, проверит целостность и число старых записей. Неизвестная/изменённая схема отклоняется; исходник не изменяется. Затем проверьте данные и пользовательские сценарии копии, сохраните резервную копию и только после этого измените `DATABASE_URL`. Подробности и ограничения — `docs/MIGRATION.md`.

Для уже версионированной PostgreSQL строго версии v0.5 сначала сделайте и проверьте резервную копию, остановите запись, выполните миграцию на копии и протестируйте перед переключением. Для неверсированной PostgreSQL v0.4/v0.5 безопасный автоматический путь пока не реализован; не ставьте Alembic stamp наугад. Новую пустую PostgreSQL настройте через `DATABASE_URL=postgresql+psycopg://…`, `AUTO_CREATE_SCHEMA=false`, затем запустите `python -m alembic upgrade head`.

## Docker Compose

Docker в среде разработки недоступен: YAML проверен ранее, **сборка и запуск не проверены**. Локальная конфигурация для пробного запуска:

```bash
cp .env.docker.example .env.docker
# заполните два одинаковых hex-пароля, BOT_TOKEN и OWNER_TELEGRAM_IDS
docker compose --env-file .env.docker up --build
```

Используйте новый пустой volume. API привязан к localhost, experimental pairing выключен. Не используйте `down -v`, если данные нужно сохранить. Это не production-конфигурация.

# Только выделенная тестовая PostgreSQL: тесты создают и удаляют случайные схемы
